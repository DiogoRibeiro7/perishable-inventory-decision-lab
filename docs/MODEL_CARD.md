# Forecasting Model Card

## Scope

Card version: `model-card-v1`

Package version: `0.2.0`

Owner: forecasting

## Intended Use

The forecasting model estimates future store-product demand distributions for perishable replenishment planning. It is intended for batch evaluation, simulation, and order recommendation workflows in this repository.

It is not evidence of real retailer impact. Current committed evidence is synthetic, fixture-based, or assumption-based unless a linked report states otherwise.

## Prediction Target And Horizon

Target: daily demand in product units.

Supported representations:

- Marginal daily quantiles for forecast evaluation.
- Cumulative horizon distributions or scenario paths for decisions.

The decision contract requires the forecast horizon to equal review period plus lead time. Evidence: `tests/test_decision.py`, `docs/FORECAST_DECISION_CONTRACT.md`.

## Training Data And Features

Training data is generated by `generate_daily_demand` or supplied through validated daily retail contracts. Canonical retail rows separate `observed_sales` from `latent_demand_estimate` and carry `latent_demand_training_weight` for rows whose sales may be availability-constrained. Feature generation uses lagged demand, rolling demand summaries, calendar features, store codes, product codes, price, and commercial-event features where available.

Point-in-time feature rules are documented in `docs/FEATURE_STORE_LINEAGE.md` and tested in `tests/test_feature_store.py`.

## Censoring And Cold Starts

Observed sales can understate latent demand during stockouts. The default demo trains on the configured latent-demand estimate and uses row weights to exclude censored rows under the conservative setting. Censoring strategies are documented in `docs/LATENT_DEMAND_CARD.md` and tested in `tests/test_demand_censoring.py`.

Cold-start and hierarchy fallbacks are documented in `docs/HIERARCHICAL_FORECASTING.md` and tested in `tests/test_hierarchical_forecasting.py`.

## Algorithms And Calibration

The default model is the package quantile forecaster. Intervals can be adjusted with conformal calibration. Evidence: `tests/test_conformal.py`, `reports/example_run/forecast_metrics.json`.

## Known Failure Modes

- Hidden lost demand can bias forecasts when stockouts censor observations.
- Promotions and event features are predictive, not causal evidence.
- Product identity changes can corrupt history unless point-in-time mappings are used.
- Distribution shift can break calibration and coverage.
- Sparse demand can make segment metrics unstable.

## Fallback And Retraining

Fallbacks include hierarchy-level baselines, conservative decision policies, and previous valid batches. Retraining requires separated training, calibration, and test windows plus updated card metadata when interfaces, assumptions, or artifact versions change.
